# ADR 0001: Use Go 1.27

- Status: Accepted
- Date: 2026-10-31

## Context

Jevlar is a thin, self-hosted gateway for decision-model APIs. Three
languages were viable: Rust (shared workspace with existing Rust services),
Zig, and Go. We measured all three on one host — 300-byte JSON POST via wrk
over loopback, at direct-upstream latency and with a 40 ms injected upstream:

```
                            req/s     mean      at 40 ms upstream
direct upstream            51,732    1.50 ms    41.23 ms
Rust (hyper)               23,464    2.71 ms    41.78 ms  (+0.55)
Zig (naive, no pool)        3,895   16.16 ms    41.81 ms  (+0.58)
Go (httputil.ReverseProxy)  8,751    7.43 ms    42.07 ms  (+0.84)
```

The Go row used `httputil.ReverseProxy` as a convenient baseline; Jevlar
ships a custom handler (response buffering, commit-after-read, model splice),
so this is a floor on Go's behaviour, not a ceiling. At production latency
all three candidates differ by under a millisecond — the measurement says
the language choice is not a performance decision.

## Decision

Implement Jevlar in Go, pinned to Go 1.27. Rust would be right only if the
code had to share a workspace with an existing Rust service; Zig is
excluded because 0.17 removed `std.net` and `std.posix.socket`. Go wins on
the ecosystem this project needs on day one: strict TOML decoding with
unknown-field rejection, mature validation tooling, Prometheus, SIGHUP-based
reload prior art.

## Direct dependencies and reasons

Maximum eight direct dependencies, each justified here against a stdlib
implementation. Standard library always wins when it is sufficient.

1. `github.com/pelletier/go-toml/v2` — the standard library has no TOML
   codec. go-toml/v2 provides strict decoding (`DisallowUnknownFields`),
   which fail-closed configuration requires: unknown keys must be rejected
   with a field path, not silently ignored.
2. `github.com/prometheus/client_golang` — the standard library exposes no
   Prometheus text format. client_golang provides a private-registry model
   (no process-global registration), label handling and the canonical
   exposition format that existing monitoring stacks scrape.
3. `github.com/klauspost/compress` — the official provider SDK zstd-compresses
   request bodies by default once they pass 1 KiB, and Jevlar cannot route a
   request whose `model` it cannot read. The standard library has no
   importable zstd decoder (`internal/zstd` is internal to `net/http`), so
   this pure-Go decoder is required for correctness with the official client.
   It is used only to inspect a copy of the body; the bytes forwarded upstream
   stay exactly as received unless a model rewrite is needed.
4. `github.com/prometheus/common` — test-only in Jevlar: the metrics test
   re-parses Jevlar's own `/metrics` output with the canonical Prometheus
   text parser, which is what `promtool check metrics` does. It is already a
   transitive dependency of client_golang, so it adds no new code to the
   binary; the module requirement is direct because the test imports it
   explicitly.

All four are added at project foundation; later additions (for example fsnotify)
require a new ADR entry before they may be added. `go mod tidy` must produce
no diff, and `govulncheck ./...` must be clean at every release.

## Consequences

- The proxy's overhead budget (p50 ≤ 2 ms at 40 ms upstream) is committed in
  `gates/thresholds.toml` and enforced against a benchstat baseline.
- The dependency budget is a policy, not an aspiration: exceeding eight
  direct dependencies requires superseding this ADR.
